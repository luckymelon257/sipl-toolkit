# Мова SIPL, розширення SIPL-R і мова анотацій

Формальні граматики записано у W3C EBNF:
- [grammar/sipl.ebnf](../grammar/sipl.ebnf): базова SIPL;
- [grammar/sipl-r.ebnf](../grammar/sipl-r.ebnf): рекурсивне розширення;
- [grammar/assertions.ebnf](../grammar/assertions.ebnf): мова тверджень.

Ця специфікація зафіксована в репозиторії і є пріоритетною для проєкту.

## Базова SIPL

БНФ курсу (Нікітченко 2020, табл. 1.2; практикум 2024, с. 8):

```text
P ::= begin S end                                                  NP1
S ::= x := a | S1 ; S2 | if b then S1 else S2 | while b do S
    | begin S end | skip                                           NS1–NS6
a ::= n | x | a1 + a2 | a1 - a2 | a1 * a2 | (a)                    NA1–NA6
b ::= a1 = a2 | a1 > a2 | b1 ∨ b2 | ¬b | (b)                       NB1–NB5
```

Ця БНФ неоднозначна. Однозначність забезпечують правила з Нікітченка (с. 10), і парсер їх дотримується:

- **Асоціативність:** усі бінарні операції лівоасоціативні. `A - B - C` означає `(A - B) - C`, а `S1; S2; S3` означає `(S1; S2); S3`.
- **Пріоритет** від найвищого до найнижчого: `*`, `+ -`, `= >`, `¬`, `∨`, `:=`, `while`, `if`, `;`.

Наслідки пріоритетів:
- `while b do S1; S2` розбирається як `(while b do S1); S2`;
- `¬M = N` розбирається як `¬(M = N)`;
- `if b then S1 else S2; S3` розбирається як `(if …); S3`.

### Лексика

| Що | Правило |
|----|---------|
| Змінна | `[A-Za-z][A-Za-z0-9_]*`. Регістр має значення, ключові слова не можуть бути змінними. |
| Число | `[0-9]+`. Мінус перед числом у позиції операнда входить у літерал (`-1`). Унарного мінуса немає: замість `-X` пишуть `0 - X`. |
| Ключові слова | `begin end if then else while do skip or not` (у SIPL-R ще `program func`) |
| Коментар | `//` до кінця рядка |
| Анотація | `//@ ключ: твердження` (див. нижче) |

Символи з підручника приймаються як синоніми:

| Синонім | Означає |
|---------|---------|
| `∨` | `or` |
| `¬` | `not` |
| `–` (тире), `−` (знак мінус) | `-` |
| `∗`, `×` | `*` |

Рядки можна завершувати як `\n`, так і `\r\n`; позиції в діагностиці від цього не зсуваються.

## SIPL-R: рекурсивні функції

Розширення взято з Нікітченка, §5.7.3, табл. 5.1–5.2, і практикуму, ПР 7:

```text
P   ::= … | program dec1; …; decn begin S end                     P2
dec ::= func fn = a | func fn(x1, …, xn) = a                       DF1, DF2
a   ::= … | if b then a1 else a2 | fn | fn(a1, …, an)              A8, A9 (CF1, CF2)
b   ::= … | a1 < a2
```

Правила розширення:
- **Порівняння `<`** (`less`) додано, бо його використовують рекурсивні приклади курсу.
- **Умовний вираз** `if b then a1 else a2`: гілка `else` простягається вправо якомога далі. Тому `if X < Y then 0 else f(X - Y, Y) + 1` означає `… else (f(X - Y, Y) + 1)`.
- **Ім'я функції без дужок** означає виклик без аргументів (CF1). Тому імена функцій не можна присвоювати і не можна вживати як змінні.
- **Функції не змінюють стан**, бо їхні тіла є виразами.
- **Тіло функції може читати змінні, яких немає серед параметрів.** Вони беруться зі стану, у якому зроблено виклик. Так працює локальна суперпозиція, про це попереджає `W002`.
- **Порядок оголошень довільний.** Функції можуть викликати одна одну, зокрема взаємно рекурсивно.

## Анотації та мова тверджень

| Анотація | Значення |
|----------|----------|
| `//@ pre: P` | передумова програми |
| `//@ post: Q` | післяумова програми |
| `//@ invariant: I` | інваріант найближчого наступного циклу `while` |
| `//@ variant: t` | варіант (обмежувальна функція) найближчого наступного циклу |

Твердження будуються як умови SIPL з додатковими операціями:

| Операція | Запис |
|----------|-------|
| кон'юнкція | `∧`, `and` |
| імплікація | `→`, `=>` (правоасоціативна) |
| порівняння | `<`, `≤ <=`, `≥ >=`, `≠ !=` |
| степінь | `^` (правоасоціативний) |
| ділення з округленням униз та остача | `div`, `mod` |
| функції | `gcd(a, b)`, `abs(a)` |
| логічні константи | `true`, `false` |

Особливості мови тверджень:
- **Ghost-змінні.** Змінні, що трапляються лише в анотаціях, є логічними: вони позначають сталі значення, наприклад початкові `x`, `y`.
- **Порядок обчислення сполучників — зліва направо:** `false ∧ ⊥ = false`, `false → ⊥ = true`. Тому вартові умови варто ставити першими, наприклад `Y ≥ 0 ∧ X ^ Y = …`.
- **Невизначені значення:** `x div 0` і від'ємний показник степеня не визначені.

## Діагностика

| Код | Рівень | Значення |
|-----|--------|----------|
| E001 | error | неочікуваний символ |
| E002 | error | операція є лише в анотаціях (`div`, `mod`, `≤`, `∧`, …) |
| E003 | error | неправильна анотація (невідомий ключ) |
| E004 | error | повторна анотація того самого виду |
| E005 | error | `invariant`/`variant` без циклу після нього |
| E006 | error | невідома функція в анотації (доступні `gcd(a, b)`, `abs(a)`) або неправильна кількість аргументів |
| E100 | error | синтаксична помилка: що очікувалось і що знайдено. Окремі пояснення для `;` перед `end` і перед `begin`. |
| E101 | error | ціле число поза допустимим діапазоном |
| E300 | error | невідома функція |
| E301 | error | неправильна кількість аргументів |
| E302 | error | функцію оголошено двічі |
| E303 | error | параметр повторюється |
| E304 | error | присвоєння імені функції |
| E305 | error | параметр має ім'я функції |
| W001 | warning | змінна може читатися до присвоєння (вона буде вхідною) |
| W002 | warning | тіло функції читає змінну, яка не є параметром |
| V001 | error | (`verify`) цикл без інваріанта |
| V002 | error | (`verify`) програма з викликами функцій |
| V003 | warning | (`verify`) спадання варіанта не перевіряється: внутрішній цикл змінює його змінні |

Кожна діагностика має `SourceSpan`: рядок і колонка рахуються з 1, зміщення з 0. CLI показує фрагмент коду з `^^^` під проблемним місцем.
