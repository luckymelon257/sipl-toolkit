# Рекурсія та найменша нерухома точка (REC-01…03)

## Семантика рекурсивної функції

Для оголошення `func f(x1, …, xn) = a` будується функціонал `φ(f) = sem_A(a)`. Рекурсивні виклики в ньому є локальними суперпозиціями в символ `f`:

```text
φ(f) = IF(S^2(less, X⇒, Y⇒), 0, S^2(add, S^[X,Y](f, S^2(sub, X⇒, Y⇒), Y⇒), 1))
```

Суперпозиція і `IF` неперервні. За теоремою Кнастера–Тарського–Кліні рекурсивне визначення задає найменшу нерухому точку `f = ⊔ fk`. Її знаходять методом послідовних наближень:

```text
f0 = ⊥,   f(k+1) = φ(fk).
```

## Побудова апроксимацій (REC-02)

`approximationTerms(program, f, k)` ([src/fixpoint/approx.ts](../src/fixpoint/approx.ts)) будує терми `f0 … fk`. Кроки:

1. **Підстановка.** У `φ` символ `f` замінюється термом попередньої апроксимації.
2. **Спрощення за строгістю суперпозиції** (як у практикумі та прикладі 5.1):
   ```text
   S(…, ⊥, …) = ⊥        S^[…](⊥, …) = ⊥        IF(b, ⊥, ⊥) = ⊥
   ```
   Звідси `f1 = IF(S^2(less, X⇒, Y⇒), 0, ⊥)`, а `f2` має вигляд із практикуму з підставленою `f1`.
3. **Допоміжні функції.** Якщо в програмі кілька функцій, вони апроксимуються одночасно (у добутку областей). Тому допоміжні функції (`one`, `sq` у [rec-power.sipl](../examples/rec-power.sipl)) на кроці `k` теж замінюються своїми k-ми апроксимаціями.
4. **Розмір.** Терм `f(k+1)` містить `fk` за посиланням, тож у пам'яті ланцюг займає лінійний обсяг. Друкуються лише терми до ~2000 символів; довші показуються як `φ(f(k-1))`.

Застосування `fk` до стану використовує ті самі формули AF_*, що й інтерпретатор. З `--explain` видно кожен крок, як у практикумі:

```text
f2([X ↦ 7, Y ↦ 4]): AF_CALL … ([X ↦ 7, Y ↦ 4] ∇ [X ↦ 3, Y ↦ 4]) … = 1
```

Runtime повної рекурсії (`sipl run`) обчислює виклик на «рівні ∞». Обчислення на скінченному рівні `k` еквівалентне застосуванню `fk`; тест [approx.test.ts](../tests/approx.test.ts) звіряє обидва способи на сітці станів.

## Тестування і візуалізація (REC-03)

```bash
sipl approx examples/rec-div.sipl -k 6 --grid X=0..20,Y=1..6 --expect "X div Y" --where "X ≥ 0" --html report.html
```

| Опція | Що задає |
|-------|----------|
| `--grid` | декартову сітку тестових станів (до 10 000 станів) |
| `--where` | фільтр станів |
| `--expect` | функцію, до якої мають збігатися апроксимації (мова тверджень) |

Звіт ([src/fixpoint/report.ts](../src/fixpoint/report.ts)) містить:
- **таблицю значень** `f0 … fk` на кожному стані (⊥ — не визначено) і стовпець `first`: номер першої визначеної апроксимації;
- **монотонність** `fi ⊑ f(i+1)`: визначене значення не змінюється і не зникає в наступних апроксимаціях;
- **порівняння з `--expect`** на першій визначеній апроксимації. Якщо очікувана функція сама не визначена (наприклад, ділення на 0), стан позначається `n/a` і не рахується як невідповідність;
- **кількість станів, де визначена кожна `fi`**, і номер, з якого визначена частина перестає зростати.

HTML-звіт ([src/fixpoint/render.ts](../src/fixpoint/render.ts)) генерується з реальних даних. Він містить:
- **теплову карту** для однієї або двох змінних: колір клітинки показує, на якій апроксимації стан стає визначеним;
- **стовпчикову діаграму** збіжності;
- **повну таблицю значень.**

Для ділення видно, що `fk` визначена саме на `x < k·y`. Тобто вхід `(x, y)` стає визначеним на `k = x div y + 1`, і це перевіряє тест.

## Межі автоматизації

- **Апроксимації обчислюються на скінченній множині тестових станів.** Твердження про загальний вигляд `fk` (наприклад, «`fk` визначена на `x < k·y`») інструмент підтверджує лише на сітці, а не доводить.
- **Глибина рекурсії обмежена** (за замовчуванням 1000 вкладених викликів). Довша рекурсія повідомляється як `call-depth`, а не зависає.
